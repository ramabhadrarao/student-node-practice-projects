Student Auth API

Copy-paste these curl commands (or import into Postman). Backend runs on http://localhost:5000.

curl Basics: Flags Explained

These are common curl options used in the examples below:

Flag Meaning Example
-i Include HTTP response headers in the output. curl -i http://localhost:5000/
-X Specify the HTTP method (e.g., POST, GET, PUT). curl -X POST http://localhost:5000/api/auth/login
-H Add a request header (e.g., set Content-Type or Authorization). curl -H "Content-Type: application/json" ...
-d Send request body data (JSON in our examples). Using -d implies POST unless you also set -X explicitly. curl -d '{"email":"a@b.com","password":"123"}' ...

Tip: -d is the short form of --data. For JSON bodies, always include -H "Content-Type: application/json".

Health Check

Quickly test if the server is running.

curl -i http://localhost:5000/

Register

Create a new user. Fields: name, email, password.

curl -i \
  -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Student One",
    "email": "student1@example.com",
    "password": "pass1234"
  }'

Tip: Status 201 means success. If you see 409, the email is already registered.

Login

Login with email and password. Returns a JWT token and user info.

curl -i \
  -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "student1@example.com",
    "password": "pass1234"
  }'

Sample successful response:

{
  "message": "Login successful",
  "token": "<JWT_TOKEN>",
  "user": { "id": "...", "name": "Student One", "email": "student1@example.com" }
}

Copy the token value. You will need it for the Me endpoint.

Me (Current User)

Fetch the logged-in user. Requires the Authorization: Bearer <token> header.

# Replace <JWT_TOKEN> below with the token from Login
curl -i \
  http://localhost:5000/api/auth/me \
  -H "Authorization: Bearer <JWT_TOKEN>"

If you get 401 (Unauthorized), your token is missing or invalid.

Postman Notes

  • Register: method POST, Body → raw, type JSON, paste the register JSON.
  • Login: method POST, Body → raw, type JSON, paste the login JSON; copy returned token.
  • Me: method GET, add Header Authorization with value Bearer <JWT_TOKEN>.

That’s it! This backend is intentionally simple for learning.

Environment

Default local setup:

MONGO_URI=mongodb://localhost:27017/student-auth
PORT=5000
JWT_SECRET=supersecret123

Set these in backend/.env and restart the server if you change them.

HTTP Status Codes (Errors & Success)

Quick meanings of common HTTP status codes you’ll encounter with this API.

Code Name Meaning When you’ll see it here
200 OK Request succeeded, response contains data. Successful login and me requests.
201 Created New resource created. Successful register creates a user.
204 No Content Request succeeded, no body returned. Not used in this demo, but common for deletes.
400 Bad Request Request is invalid or missing fields. Missing email/password on login; missing fields on register.
401 Unauthorized Missing or invalid authentication token. Calling me without a valid Bearer token; wrong login password.
403 Forbidden Authenticated, but not allowed to perform action. Not used in this demo, but common for role-based access.
404 Not Found Requested resource doesn’t exist. me if the user ID doesn’t exist anymore.
409 Conflict Request conflicts with current state. register when email is already taken.
422 Unprocessable Entity Semantically invalid data. Not used here; typical for detailed validation errors.
429 Too Many Requests Client is rate-limited. Not used here; common when limiting login attempts.
500 Internal Server Error Unexpected error on the server. Any unhandled exception in the backend code.
503 Service Unavailable Server is down or overloaded. Database unavailable or server startup issues.

Tip: Check the status code first. 2xx = success, 4xx = client-side issue (fix your request), 5xx = server-side issue.

Source: Express + Mongoose + JWT. For students: passwords are hashed with bcrypt, tokens signed with JWT.
